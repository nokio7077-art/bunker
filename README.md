# Бункер онлайн

Браузерная игра для 5–16 участников: комнаты по шестизначному коду, девять личных карточек, общая катастрофа и бункер, последовательные ходы и тайное голосование. Интерфейс на русском, адаптирован к телефонам. В колоде 500 профессий с короткими описаниями; личные карточки и сценарии отредактированы на основе списков пользователя. Особые условия — одноразовые действия с кнопкой применения; фобия выдаётся отдельной карточкой.

Профессии хранятся в [professions.js](professions.js), сведения об отборе — в [docs/professions-selection.md](docs/professions-selection.md). При начальной раздаче профессии не повторяются. Особое условие со случайной заменой может создать совпадение. Новая колода используется при старте новых партий.

Карточка «Биология»: пол, случайный возраст от 15 до 105 лет включительно, ориентация и стерильность. Для мужчин варианты ориентации — гетеро, гей, би, асексуален; для женщин — гетеро, лесбиянка, би, асексуальна. Игровые вероятности ориентаций: гетеро — 93%, гей/лесбиянка — 3%, би — 3%, асексуальность — 1%. Это настройка баланса, а не оценка распространённости среди реальных людей. Стерильность выбирается независимо от остальных характеристик. Новые правила генерации применяются при раздаче новой партии; уже выданные карточки сохраняют свои значения.

## Колоды и совместимость

В `data/` находятся 23 катастрофы, 81 убежище, 159 карточек здоровья, 90 фобий, 173 предмета багажа, 131 хобби, 50 интересных фактов и 25 исходных конфликтных черт характера. К чертам добавляются 16 прежних спокойных вариантов. Исходные названия (включая «Расист», «Гомофоб», «Ксенофоб» и остальные) сохранены; описания характеризуют вымышленного персонажа и не назначают обязательный голос. 16 особых условий описаны в `special-cards.js`, их действия проверяются сервером в `special-actions.js`. Описания всех 500 профессий хранятся в `profession-descriptions.js`.

Генератор выбирает катастрофу, затем совместимое убежище: проверяет защиту воздуха и воды, отопление, карантин, стартовые запасы и отдельные географические ограничения. Вместимость равна половине первоначальной группы с округлением вниз. Срок восстановления отличается от начальной обязательной изоляции; долгосрочное пополнение запасов остаётся задачей обсуждения. Ресурсы и сроки — игровые сценарные параметры.

В раскрывающемся блоке бункера видны еда, вода, энергия, оснащение и проблемы. Описание профессии и других личных карточек остаётся скрытым от остальных до раскрытия. Отдельные карточки здоровья и жизненного опыта проверяются на совместимость с полом, возрастом и радиационным сценарием. Сохраняется шанс здорового персонажа.

Подробности: [разбор карточек](docs/card-review.md), [матрица 1863 сочетаний](docs/disaster-bunker-compatibility.csv), [журнал правок](docs/card-edit-log.md). Старые партии сохраняют разданные значения и прежний формат бункера; для проверки новых колод начните новую.

## Изображения катастроф

23 присланные PNG-карточки перенесены из корня в `public/images/cards/disasters/`. Содержимое файлов не изменено. Номер файла соответствует ID катастрофы: `1.png` — ядерный обмен, `21.png` — зомбиапокалипсис, `22.png` — восстание машин, `23.png` — инопланетное вторжение. Соответствие, названия и размеры записаны в `public/card-images.js`.

После старта каждый участник видит изображение выпавшей катастрофы целиком на весь экран. Кнопка **«О ужас! Дальше»** открывает комнату. **«Читать текст»** показывает обычное описание и параметры крупным шрифтом; оттуда можно вернуться к изображению. В комнате кнопка **«Открыть карточку катастрофы»** позволяет посмотреть её снова. Просмотр запоминается отдельно для роли и комнаты, поэтому после перезагрузки экран не мешает продолжать игру. Старые партии без ID и ошибки загрузки изображения используют текстовое представление.

Сервер отдаёт только изображения, перечисленные в реестре. Браузер получает облегчённые WebP, а при ошибке загрузки карточки пробует исходный PNG. WebP имеют хеш содержимого в имени и кэшируются на год; оригиналы используют проверку ETag. Каталоги данных, сохранения и остальные файлы репозитория не становятся публичными. При добавлении новой картинки внесите запись в `public/card-images.js`, выполните `node scripts/optimize-images.mjs` (нужен ffmpeg) и перезапустите сервер. Скрипт обновит реестр, ссылки в CSS и удалит устаревшие производные WebP, сохранив PNG. В текущей загрузке есть только катастрофы; изображений бункеров нет.

## Главная страница и телефоны

Главная оформлена по присланному зелёному пиксельному макету: пейзаж с бункером, рамки, блок статистики и полноценная форма создания/входа. Фон подготовлен по пользовательскому референсу и хранится в `public/images/ui/bunker-landscape.png`; интерфейс остаётся обычным HTML. Оформление и адаптивные правила вынесены в `public/theme.css`.

Шрифт заголовков Rubik Mono One с кириллицей раздаётся локально из `public/fonts/` вместе с лицензией OFL. Внешние Google Fonts не требуются. На узких телефонах карточки переходят в одну колонку, поля ввода используют размер 16 px, длинные названия переносятся. Во время голосования список участников располагается перед личным досье. Диалоги и экран катастрофы учитывают доступную высоту экрана.

## Запуск

Нужен Node.js 22 или новее. Внешних зависимостей нет.

```sh
cd /workspace/bunker
npm start
```

Сервер слушает порт 3000 на всех интерфейсах. `PORT`, `HOST` и `DATA_DIR` можно переопределить переменными окружения. Проверка работоспособности: `GET /health`. Для разработки: `npm run dev`. Для тестов: `npm test`.

## Правила

### Проверить одному или вдвоём

Создайте комнату и нажмите **«Тестовая игра с ботами»**. Кнопка доступна ведущему, пока в комнате меньше пяти человек. Игра добавит виртуальных участников до пяти и начнёт партию по обычным правилам.

Открывайте свои карточки и передавайте слово. На ходе виртуального участника нажимайте **«Ход бота»**: он откроет профессию в первом круге или случайную закрытую карточку в следующих, затем передаст слово. Во время голосования нажмите галочку у выбранного участника: голос отправится сразу. Когда проголосуют все люди, боты проголосуют автоматически. Боты голосуют случайно и продолжают голосовать после изгнания. Изгнанный ведущий сохраняет управление ботами. Если тестируют двое, каждый сам выполняет свои ходы и голосует со своего устройства.

Тестовые комнаты явно помечены. Закрытые карточки ботов и других людей скрыты даже от ведущего. Для обычной партии создайте новую комнату и пригласите друзей.

Боты сами не применяют особые условия. Свою карту действия можно проверить кнопкой «Применить условие» в свой ход.

### Особые условия и фобии

У каждого игрока одно особое условие. Оно применяется один раз за партию, только в свой ход и до изгнания. Кнопка открывает описание эффекта и выбор участника для сброса или обмена; окончательное применение меняет состояние комнаты у всех участников. Сервер проверяет очередь хода, совместимость и повторное использование. Действие раскрывает само особое условие и не заменяет обычное раскрытие за ход. Можно сначала раскрыть условие как обычную карточку, а применить в одном из следующих собственных ходов.

- **Сброс:** здоровье, фобия, характер или хобби любого участника, включая себя и изгнанных. Значение удаляется, остаётся публичный пустой слот. Прежняя закрытая карточка не раскрывается.
- **Случайная замена:** своя профессия, здоровье, фобия, багаж, хобби, характер или интересный факт. Сервер случайно выдаёт другую подходящую карточку; учитываются биология и катастрофа. Игрок не выбирает результат, прежняя карточка исключается. Возможны совпадения с чужими картами. Список вариантов не передаётся клиенту.
- **Обмен:** профессия, багаж или хобби с другим участником. Открытость привязана к слоту игрока, а не к передаваемой карточке. Можно передать пустой слот; пустота всегда публична.
- **Перетасовка:** открытый багаж или открытые хобби всех участников, включая изгнанных. Нужно минимум две непустые открытые карточки. Закрытые и сброшенные слоты не участвуют; случайность допускает сохранение прежнего владельца.

Фобии взяты из нового присланного списка: 100 позиций сведены к 90 после объединения повторов и исправления названий. Это игровые страхи и особенности, без автоматического запрета действий или обязательных голосов. Подробности — в [журнале правок](docs/card-edit-log.md). Из здоровья удалена «Смертельная семейная бессонница», «Хроническая бессонница» сохранена. Новые колоды выдаются в новых партиях; старые сюжетные условия не превращаются в действия посреди игры.

### Обычная партия

1. Ведущий создаёт комнату, друзья входят по коду. Старт доступен при 5–16 игроках.
2. После старта каждый участник видит полноэкранную катастрофу. Кнопка **«О ужас! Дальше»** открывает комнату; просмотр запоминается для этой роли и комнаты в браузере. В первом круге каждый раскрывает профессию, рассказывает о своей пользе и передаёт слово.
3. В следующих кругах каждый раскрывает одну оставшуюся карточку. Когда все полученные карточки раскрыты или сброшены, можно передавать слово без новой карточки.
4. Первое голосование для 5 / 6 / 7 / 8+ игроков — после 4 / 3 / 2 / 1 круга. Затем после каждого круга.
5. Все игроки, включая изгнанных, подают один неизменяемый голос за живого участника. Можно голосовать за себя. Итог появляется после голосов всех участников. При равенстве среди лидеров выбирается случайный участник.
6. Игра заканчивается, когда остаётся половина первоначального состава с округлением вниз. После окончания видны все карточки.

Играйте за одним столом: каждый участник открывает сайт на своём телефоне и входит в общую комнату. Обсуждайте карточки вслух. Голосовой чат не нужен. Участники должны оставаться доступными: автоматического пропуска ходов и голосов нет.

## Бесплатная публикация

[Развернуть игру на Render](https://render.com/deploy?repo=https://github.com/nokio7077-art/bunker)

1. Откройте ссылку, войдите в Render через GitHub и разрешите доступ к репозиторию `nokio7077-art/bunker`.
2. Создайте сервис из Blueprint. Файл `render.yaml` задаёт бесплатный тариф, запуск сервера и проверку `/health`. Убедитесь, что выбран план **Free**.
3. Дождитесь успешной сборки и состояния **Live**. Render покажет HTTPS-адрес игры. Откройте его на двух устройствах, создайте комнату на одном и присоединитесь по коду на другом.
4. Отправляйте друзьям адрес сайта. Для каждой партии ведущий создаёт новую комнату, остальные вводят её код. Для старта нужно минимум 5 игроков.

Изменения в подключённой ветке `main` будут запускать новую публикацию автоматически. Не обновляйте сайт во время партии.

На бесплатном тарифе сервер может засыпать без запросов; первый вход после паузы может занять некоторое время. Локальный диск непостоянный: при повторном развёртывании или пересоздании экземпляра комнаты могут исчезнуть. Сохранение в браузере не восстанавливает удалённую сервером комнату. Для первых игр небольшой компанией это допустимый вариант, если создавать новую комнату перед партией.

Для постоянного сохранения выберите в Render платный экземпляр с диском, смонтируйте диск в `/var/data/bunker` и задайте `DATA_DIR=/var/data/bunker`. Бесплатная конфигурация в репозитории не создаёт платных ресурсов. Изменения тарифов выполняются в аккаунте владельца.

GitHub Pages не подходит для запуска этого приложения целиком: он не выполняет `server.js`. Синхронизация комнат и защита закрытых карточек требуют Node.js-сервера.

## Сохранение и доступ

Комнаты и роли сохраняются в `.data/rooms.json`, с атомарной заменой файла. Перезапуск одного сервера сохраняет партии. Токен игрока хранится в localStorage браузера; не передавайте его другим. Очистка данных браузера приводит к потере роли. Карточки фильтруются сервером: другие игроки не получают закрытые значения и чужие токены. Изменения загружаются каждые 1,5 секунды.

Для игры через интернет нужен один постоянно работающий экземпляр сервера с постоянным диском и HTTPS через reverse proxy. Не запускайте несколько серверов с общим файлом данных. Комнаты пока не удаляются автоматически. Хранилище содержит личные карточки и токены: ограничьте доступ и резервируйте его. Сервер включает ограничение частоты действий, проверку Origin и CSP; аккаунты, модерация и восстановление потерянных ролей ещё не реализованы.

## Облачная среда

Работайте в существующем checkout `/workspace/bunker`; отдельный Git worktree не нужен. Установки пакетов не требуется. После восстановления среды запустите `npm start` заново: процессы не сохраняются вместе с файлами. Выполните `npm test` и проверьте `/health`. Публикация в интернете выполняется отдельно.

### Анимация главной страницы

Фон использует `public/videos/bunker-entrance.mp4`: десятисекундное видео без аудиодорожки, H.264 с faststart (около 1,7 МБ). Воспроизводится по кругу и внутри страницы на телефонах. Кнопка паузы сохраняет выбор в браузере; скрытая вкладка останавливает воспроизведение. При системной настройке уменьшения движения или экономии трафика видео не загружается автоматически. Статичный фон остаётся доступным при ошибке загрузки или запрете автозапуска. Сервер поддерживает запросы диапазонов байтов для мобильных браузеров.

### Обновление игрового экрана

Шапка комнаты стала компактнее; код расположен в отдельной кнопке копирования внутри общей обложки. Голос отправляется одним нажатием на галочку без отдельного подтверждения.

Характеров теперь 100, все с описаниями: сохранены исходные 25 конфликтных и 16 обычных черт, добавлены ещё 59. Новые характеры и вероятности биологии применяются при новой раздаче; текущие карточки не меняются.

После особого условия все видят последний результат в отдельном блоке: участника, категорию и открытые значения до/после. Закрытые значения никогда не попадают в публичный журнал или события. Результаты сохраняются вместе с комнатой; историю можно прочитать в журнале. Прошлые события, созданные до обновления, не реконструируются.

### Финал и сведения о мире

По завершении партии каждый участник видит личную финальную заставку: оставшиеся внутри — «Вы выжили», изгнанные — «Попрощайтесь с миром». Два предоставленных видео оптимизированы и воспроизводятся без звука; автоматически проигрываются один раз и остаются на последнем кадре. Подписи уже встроены в видео, дополнительных надписей и управления воспроизведением нет. Крестик закрывает карточку и возвращает к итогам. Просмотр запоминается в браузере, финальную карточку можно открыть снова.

Блок катастрофы и бункера сворачивается; на телефонах изначально свёрнут. Выбор сохраняется при обновлениях и перезагрузке.

Для всех 23 катастроф начальная изоляция составляет 90 суток — как указано на иллюстрациях. Запасы убежищ и подбор совместимых бункеров учитывают именно 90 суток. Сохранённые комнаты с прежними длительностями приводятся к этому сроку при запуске сервера. Общая фраза про закрытые отсеки удалена из колоды бункеров.

### Очередь досье и следующая партия

Во время чужого хода на месте личного досье показаны только открытые карточки текущего участника. При смене выступающего текущая позиция прокрутки сохраняется; свои карты доступны ниже в раскрываемом разделе. Во время голосования сохраняется список участников для выбора.

После завершения ведущий нажимает «Следующая партия тем же составом». Комната, код, имена и сессии сохраняются. Все возвращаются в зал ожидания, старые карты, голоса и использованные условия очищаются. Следующий человек по кругу становится ведущим и начинает новую партию с первого слова. Боты при выборе ведущего пропускаются. Новый ведущий нажимает «Начать игру»; раздаются новые карты и сценарий. Номер партии сохраняется на сервере и отделяет просмотренные заставки разных партий.

Финальные видео начинаются со второй секунды исходников и длятся 8 секунд. В вертикальном положении на телефонах загружается отдельный вариант 4:3: боковой фон сокращён, встроенные надписи сохранены целиком. Статичные заставки соответствуют последнему кадру. Обычный вариант остаётся широкоформатным.


## Защита партии от остановки

- **Время хода — 3 минуты 16 секунд.** Если текущий игрок не завершил ход, сервер сам раскрывает одну доступную карточку (в первом круге — профессию), затем передаёт слово дальше. Раскрытая ранее карта повторно не открывается. Таймер обновляется при каждом новом ходе.
- **Время голосования — 2 минуты.** Не проголосовавшие участники считаются воздержавшимися. Побеждает кандидат с наибольшим числом голосов; при ничьей или отсутствии голосов игра случайно выбирает одного оставшегося в бункере. Изгнанные по-прежнему вправе голосовать. **За себя голосовать нельзя** — запрет проверяется сервером.
- **Передача ведущего.** Ведущий может назначить другого человека через кнопку в комнате. Если ведущий отсутствует более 3 минут, а другой человек проявлял активность, сервер автоматически передаёт ему эту роль. Боты никогда не становятся ведущими.
- **Восстановление места.** После создания или присоединения каждый игрок получает индивидуальный 24-символьный резервный код, который можно посмотреть и скопировать из комнаты. На главной странице откройте «Восстановить», введите шестизначный код комнаты, прежнее имя и резервный код. Сервер выдаёт новую сессию, аннулируя старый токен. Резервный код нужно сохранить вне браузера; по одному имени роль восстановить невозможно. Если сервер потерял саму комнату, её восстановление этим способом невозможно.
- **Очистка неактивных комнат.** Лобби и завершённые партии удаляются через 24 часа без активности, активные партии — через 72 часа. Планировщик проверяет время раз в минуту; при создании комнат также срабатывает очистка. Вводится предел в 500 одновременно хранимых комнат. Обновления таймера не продлевают срок хранения без действий игроков.

Серверные ограничения работают независимо от открытой вкладки; фоновые проверки продолжаются, пока экземпляр сервера запущен. Все изменения логики сопровождаются автоматическим запуском `npm test` через GitHub Actions.


## Подключение без интернета (Android-хост)

Подключите игроков к точке доступа Android, на которой установлен Termux. На телефоне-хосте:

```sh
cd ~/bunker
npm start
```

Откройте `http://localhost:3000`, создайте комнату и нажмите **«Показать QR-код приглашения»**.
QR-код содержит локальный IP телефона, порт и шестизначный код комнаты; у других игроков автоматически откроется форма входа с заполненным кодом. Игровые ресурсы и генератор QR-кодов хранятся локально, интернет не нужен. Если телефон меняет адрес сети, покажите новый QR-код после обновления страницы.

**Необязательное экспериментальное имя `bunker.local`:** можно попробовать запустить сервер командой `BUNKER_MDNS=1 npm start`. Сервер попытается объявлять `bunker.local` через mDNS. Клиенты могут открыть `http://bunker.local:3000`, **но** это работает только там, где Android/роутер/браузер пропускают mDNS; на мобильных точках доступа multicast иногда блокируется. Имя не регистрируется в глобальном DNS. Без `:3000` это имя не заработает, пока отдельный сервер не будет слушать порт 80. QR-код по IP остаётся основным поддерживаемым способом подключения.

При работе по Wi-Fi не закрывайте процесс Termux и не допускайте агрессивного энергосбережения. Доступ к комнате получают все устройства в одной сети, знающие её код.
